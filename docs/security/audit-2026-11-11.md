# Security audit, 11 November 2026

Scope: the whole project (Rust core, desktop shell, phone remote, music, interface,
importers, downloads, build pipeline). Method: code review of every place untrusted data
enters (imported files, the network, downloads, loaded libraries), dependency audits
(RustSec cargo-audit 0.23 over 528 crates; npm audit), and tests for each fix.

## Found and fixed

| # | Severity | Finding | Fix | Proof |
|---|---|---|---|---|
| 1 | High | A crafted .wptheme file could write files outside the media folder: only ".." was checked, and joining an absolute path (C:/…) replaces the folder | Only plain relative paths are accepted (`media::is_plain_relative`) | Test rejects `../`, `C:/…`, `/etc/…`, UNC shares, mixed and `C:x` paths |
| 2 | High | Bundled SQLite had a known CVE (libsqlite3-sys 0.30, RUSTSEC-2026-0459) | rusqlite 0.32 → 0.41.1 (libsqlite3-sys 0.39.1) | cargo-audit clean; all tests and real-file imports pass |
| 3 | Medium | No content-security policy: injected script could reach the internet | Strict CSP: own code, own media (asset protocol), IPC only; no eval | Songs live, PDF import (pdf.js + worker), themes, media, Identify all run with the policy enforced; nothing blocked |
| 4 | Medium | The Vosk engine (program code loaded into the app) was downloaded without an integrity check | SHA-256 of the official v0.3.45 release is pinned; a mismatch is refused; the model is checked for completeness | Test against the real release file |
| 5 | Medium | PIN guessing could be spread over many addresses to dodge the per-device limit | 20 wrong PINs a minute network-wide pauses joining; constant-time PIN check; at most 30 devices | Test with 20 addresses |
| 6 | Medium | A damaged or hostile import file could panic and crash the app | Every importer runs under a guard; locks are taken outside it so they are not poisoned | Code review |
| 7 | Medium | NDI runtime loaded by bare file name on Windows (DLL search-order planting) | Only the installer's folders are used on Windows | Code review |
| 8 | Low | PowerShell started by name (PATH could substitute another program) | Full system path | Code review |

| 10 | Low | Dev tools only: Vite/esbuild dev server readable by any website while `npm run dev` runs | Vite 6.4.6, plugin-react 4.7.0 | npm audit: 0 vulnerabilities |

## Checked and fine

- SQL: no user input is ever formatted into SQL; two formatted statements use fixed names.
- Phone remote pages: all user text is escaped; values inserted unescaped are numbers, fixed words or the server's own hex token.
- Phone remote: 128-bit random session tokens; commands go through the same checks as the desk (held output, latching); one press per 150 ms; sessions end after 6 hours idle; Origin checked on POST and WebSocket.
- Zip unpacking (presentations, Vosk) uses safe entry names.
- Presentation page uploads: token is hex-checked, page number numeric.
- Settings: only listed keys can be written.
- No secrets or passwords are stored.

## Accepted for now, with advice

- The phone remote is plain HTTP on the church network: someone on the same Wi-Fi could capture the PIN or a session. Use a password-protected network; press "End of service". HTTPS can be added later.
- The installer is not code-signed (SmartScreen warning). Needs a code-signing certificate.
- The Vosk speech model (data, not code) is not fingerprinted yet: its download site could not be reached from the audit environment. Add its SHA-256 after the first successful download.
- Dependency warnings without known exploits: proc-macro-error (unmaintained, build-time only), ttf-parser (unmaintained, reads only the computer's own fonts), glib (unsound iterator, Linux build only).
- All app windows (including outputs) may call the app's commands. With the CSP and React's escaping this needs an injection first; restricting output windows' commands is a later hardening step.
- Restore only backups you made yourself.

## Added after the audit (11 Nov 2026)

- Camera on the screens: every window starts WebView2 with `--use-fake-ui-for-media-stream`,
  which grants camera access to the app's own pages without a permission prompt (a prompt
  would appear on the projector). Safe because the CSP allows only the app's own code in
  those windows. Microphone access for speech is separate (Vosk or Windows Speech, not the
  web page). Camera ids can differ between windows: outputs fall back to the camera's name.
- Pastor's notes (phone remote, role "Pastor's notes"): up to 600 characters, one every 2 s,
  control characters removed; this role cannot drive the screens; notes never show without
  the operator.
